# pierce-dx — Spec

> Status: `ready-for-agent`. Produced from a grilling session on 2026-08-01. The implementer is Claude (post-context-compaction) in this same session — this spec is deliberately self-contained, including exact paths, commands, and machine facts verified during exploration. Where the spec says "verify at implementation time," do so before relying on the detail.

## Problem Statement

Pierce has spent months customizing his dev experience on this Mac — shell config, custom scripts, terminal theme, editor settings, keyboard remaps, AI-agent tooling, package-manager globals, and a daily auto-update system. This state lives scattered across dozens of dotfiles and install locations, with no reliable way to reproduce it on a new machine or keep multiple machines in sync. A previous attempt (`csync()` → `~/configrepo` → github.com/pkelaita/configs) was a partial, manual, one-way copy of 7 files that he forgot existed. Meanwhile, the live config has accumulated years of dead cruft (stale PATHs from old usernames, aliases for uninstalled tools, an abandoned ghostty tab-title project).

## Solution

A private GitHub repo, `pkelaita/pierce-dx`, checked out at the fixed path `~/pierce-dx` on every machine, that is the single source of truth for Pierce's DX. It is a **continuous multi-machine sync tool**; first-time machine setup is just "sync onto an empty machine."

- First-party config files live in a `home/` directory that mirrors `$HOME` path-for-path — the tree *is* the mapping (no manifest).
- Third-party tools are never vendored; a readable `setup.sh` installs the latest version of each via literal commands.
- Two scripts total: `setup.sh` (apply, sole flag `--yes`) and `diff.sh` (read-only drift report).
- A concise agent layer (`AGENTS.md`, `CLAUDE.md` containing exactly `@AGENTS.md`, and a `dx` skill installed to all agents) makes the repo fully agent-operable: capture, apply, extend, and discover workflows.
- Implementation is a **dual job**: build the repo AND clean this machine (cleanup ledger below) so live state matches the repo afterward.

## Implementation Decisions

### Repo shape

- Location: `~/pierce-dx`, hardcoded everywhere. Private repo `pkelaita/pierce-dx`, pushed after implementation (gh is already authed as pkelaita). Default branch `main`.
- Top level: `README.md`, `AGENTS.md`, `CLAUDE.md` (content: `@AGENTS.md`), `SPEC.md` (this file), `setup.sh`, `diff.sh`, `home/`, `skills/dx/SKILL.md`, `cursor-extensions.txt` (or similar single flat list; exact name implementer's choice, referenced from setup.sh).
- **`home/` mirrors `$HOME`**. Apply = walk tree, copy each file to same relative path under `$HOME`. Capture = same walk, reverse direction. Adding a synced file = dropping it in the tree. No manifest anywhere; the two machine-local diff-ignored files are a ~3-line list inside the scripts.

### `setup.sh`

- Sections, in order: (1) preflight — Xcode CLT/brew existence check, SSH key check (if no `~/.ssh/id_ed25519` or `ssh -T git@github.com` fails → print pointer to README §SSH and continue with config-only steps or exit; implementer picks the friendlier behavior); (2) brew CLI formulae; (3) brew casks: `claude-code@latest`, `codex`, `monitorcontrol`, `1password-cli`; (4) runtimes: vite-plus (official installer, viteplus.dev), bun (official installer), cursor-agent (official installer); (5) globals: `pnpm add -g sst tsx typescript`; `uv tool install pdfsplitter`, `uv tool install tox`; `gh extension install github/gh-stack` (idempotent-guard or `--force`); (6) skills via vercel skills CLI (see below); (7) `home/` tree apply with prompt/backup semantics; (8) git-clone section into `~/scripts/`; (9) allowed_signers generation; (10) MonitorControl defaults import; (11) launchd agent load; (12) summary.
- Overwrite semantics (first-party files only): identical → silent skip; absent → silent install; differs → prompt `overwrite? [y/n]` per file (in `--yes`: overwrite). Every overwrite first copies the old file to `~/Desktop/pierce-dx-backup-<YYYYMMDD-HHMMSS>/<home-relative-path>`. One backup folder per run, created lazily.
- Third-party installs: always run, install/upgrade to latest, no prompts, no backups.
- Sole flag: `--yes`. No other flags. Bash (stock `/bin/bash` 3.2-compatible — do NOT rely on bash 4+ features; test with `/bin/bash`).
- Clones (clone if absent, `git pull --ff-only` if present):
  - `git@github.com:pkelaita/awsp.git` → `~/scripts/awsp`
  - `git@github.com:pkelaita/fav.git` → `~/scripts/fav`
  - `git@github.com:ming86/cc-account-switcher.git` → `~/scripts/cc-account-switcher`
  - `git@github.com:pkelaita/Zen-Reverse-Tab-Switch-With-Ctrl-Backtick.git` → `~/scripts/zen-remap-ctrl-backtick` (clone only; do NOT run its installer — the vendored karabiner.json is the applied artifact)
- Skills: reinstall the current global set. Verified flags: `skills add <github-repo> -g -y -a '*' --skill <name,...>`. At impl time, enumerate the exact repo→skill pairs from this machine (`pnpm dlx skills ls` or `~/.agents/skills` provenance). Current global set (17): astro, convex-migration-helper, create-agentsmd, domain-modeling, find-skills, frontend-design, gh-stack, grill-with-docs, grilling, paperclip, polish, shadcn, simple-web-design, stop-slop, to-spec, turborepo, vercel-react-best-practices. EXCLUDE openlattice-sourced skills (add-connector, add-enricher, network-search, person-context) — those are project symlinks, not skills-CLI installs. Invoke the CLI as `pnpm dlx skills` (matches daily-up).
  - The repo's own `dx` skill: install via skills CLI from the local repo if supported (verify `skills add` with a local path); fallback: symlink/copy `skills/dx` into `~/.agents/skills/dx` and into each agent's skills dir the same way the CLI lays out its symlinks.
- Brew formulae (exact list): `fd gh git-lfs go-task pnpm uv awscli ripgrep htop tree docker`.
- Cursor extensions: `while read`-loop over the flat id list, `cursor --install-extension <id> || true`. Capture the list at impl time from `ls ~/.cursor/extensions` (strip version suffixes; ~38 ids). Cursor app itself is assumed installed (GUI).

### `diff.sh`

- Read-only, no flags. Walks `home/`, compares each file to its `$HOME` counterpart: `modified: <path>` (differs), `missing: <path>` (absent live), and a final count of identical files. Ignores exactly `.aws/config` and `.codex/config.toml` → reported as `ignored (machine-local): <path>`. Exit 0 always (or nonzero on drift — implementer's choice; keep agent-friendly).

### Agent layer

- `AGENTS.md` ≤ ~40 lines. Contents: what the repo is (2 sentences); the `home/` mirror convention; the two scripts; four workflows — **capture** (diff.sh → copy drifted files into `home/` → review diff → commit+push), **apply** (git pull → `./setup.sh --yes`), **extend** (new file into `home/` at its real path, or new install command into the right setup.sh section; then apply + capture + push), **discover** (audit surfaces: `brew leaves` vs setup.sh list, `pnpm ls -g`, `uv tool list`, `gh extension list`, skills list, `~/scripts` contents, new aliases/PATH lines in live shell files, config files in known locations not yet mirrored; propose candidates individually for y/n; wire accepted ones via extend); hard rules — two-tier asset model (first-party vendored / third-party install-latest), never capture `.aws/config` or `.codex/config.toml`, no `~/projects` or work artifacts (zero openlattice traces), no GUI apps except MonitorControl, previously rejected: gcloud, postgres, worktrunk, zed, Maccy/Raycast settings, macOS defaults, casks-as-GUI-apps.
- `CLAUDE.md`: exactly `@AGENTS.md`.
- `skills/dx/SKILL.md` (~10 lines): triggers on "dx repo", "sync my dx", "my dev setup", etc.; instructs: cd `~/pierce-dx`, read AGENTS.md, execute the matching workflow. Agent-agnostic wording.

### README.md

Human-readable, not verbose. Sections: what this is + annotated repo tree; **Bootstrap** (fresh machine): 1) install brew, 2) `brew install gh && gh auth login`, 3) clone pierce-dx (HTTPS via gh credential helper works pre-SSH), 4) `./setup.sh`; **SSH key setup** (the doc setup.sh points to): `ssh-keygen -t ed25519`, `gh ssh-key add` twice (auth + `--type signing`), note that allowed_signers regenerates via setup; **Manual installs** (GUI apps): cmux (recommend `brew install --cask cmux` so daily-up's `brew upgrade cmux` works; other install methods fine — the daily-up entry then fails harmlessly), Ghostty, Cursor, Sublime Text, Karabiner-Elements (required for the applied karabiner.json), Raycast (settings: manual export/import, encrypted DB), Maccy (configure in-app), Zen, 1Password, CodexBar, supacode; **Sync usage**: the four agentic workflows one line each + "or run setup.sh / diff.sh yourself"; note that `github.com/pkelaita/configs` is deprecated by this repo (archive manually if desired).

## Implementation Ethos (read first, implementer)

- **Do not make this more complex than it needs to be.** Two scripts, a mirrored tree, a few flat lists — that's the whole system. If you find yourself adding a config format, a third script, a layer of indirection, or an abstraction "for later," stop and find the simpler shape.
- Elegance here means: readable by a human in one sitting, obvious where everything lives, boring bash over clever bash, convention over configuration. The `home/` mirror carries the design — lean on it.
- Prefer deleting/omitting to guarding: a section that isn't needed shouldn't exist half-disabled.
- Every line of AGENTS.md and the skill costs agent context forever — keep trimming until it hurts, then stop.
- Nothing in this section removes or overrides any requirement above; it governs *how* to build what's specified, not *what* to build.

## Testing Decisions

- **Single seam: the `HOME` environment variable.** Both scripts must resolve every live path via `$HOME` (never hardcoded `/Users/kelaita` — the vendored *content* may contain the username where unavoidable, but script logic may not). Test by running against a throwaway home: `HOME=$(mktemp -d) ./setup.sh --yes` with third-party sections skipped or stubbed, then assert the copied tree; `HOME=<fixture> ./diff.sh` against fixtures for modified/missing/identical/ignored cases.
- Good tests exercise external behavior only: file landed at path, backup created on overwrite, identical file untouched (compare mtimes), prompt honored (pipe `n` → file unchanged), diff output lines match expectation. No testing of internals.
- Manual verification on this machine counts as the acceptance test: after cleanup + apply, `diff.sh` is clean and a fresh shell (`bash -l`) works with all aliases functional.
- No test framework — a small `test.sh` (or documented manual checklist in the PR/commit) is sufficient; this is a dotfiles repo, not a product.

## Out of Scope

- Anything in `~/projects` or work artifacts: ladder, sls-agent-credentials, openlattice skills/links — zero traces of openlattice anywhere in the repo.
- GUI app installation (except MonitorControl) — manual README list instead. No Maccy/Raycast settings, no general macOS defaults, no Zed, no gcloud, no postgres, no worktrunk.
- SSH key generation/upload; moving private keys between machines; 1Password vault contents.
- Claude Code machine state: memory dir, history, sessions, settings.local.json, `~/.claude.json`.
- cmux config (live files are untouched all-commented templates; real prefs are in-app).
- Deleting/archiving the remote `pkelaita/configs` repo (manual).
- Multi-user/multi-shell (zsh) support — bash on macOS, user kelaita-shaped machines only.

- Gotcha: `~/.claude/settings.json` may be rewritten by Claude Code at runtime; it's still the right sync target (prefs are portable). Copy model (not symlinks) was chosen precisely because tools rewrite these files.

- Gotcha: brew cask installs may need `--adopt` if an app exists in /Applications from a non-brew install (relevant only to monitorcontrol here).
- The old `csync`/`configrepo` system is fully superseded; its deletion is part of the cleanup ledger.
